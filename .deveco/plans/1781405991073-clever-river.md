## Design

### Tab Content Integration Strategy

**Key decision**: Embed page content directly in TabContent using the component builder pattern, NOT via `safePushUrl` navigation.

Rationale: Tab content should be embedded inline so the tab bar stays visible. `safePushUrl` pushes onto the Navigation stack, which hides the tab bar. For tabs, we use the component directly.

**Pattern**:
```
TabContent() {
  if (this.tabLoaded[N]) {
    RealPageComponent()   // embedded inline
  }
}
.tabBar($r('app.string.tab_label'))
```

**Decision**: Option A — keep BackButton, it just calls `safeBack()` which will be a no-op when there's nothing on the Navigation stack. Users can still navigate forward from within the page.

## Risks And Compatibility

| Risk | Mitigation |
|------|-----------|
| Pages with BackButton show useless back arrow in tab context | Acceptable for now — `safeBack()` is a no-op when Navigation stack is empty |
| HomePage layout may overflow or clip when embedded in TabContent | Test on emulator; may need to adjust scroll containers |
| Some pages may have `@Entry` decorator which could conflict when used as child components | Remove `@Entry` from pages that are embedded in tabs (HomePage, DietDiaryPage, AiChatPage, RecipeCommunityPage, SettingsPage) — `@Entry` is only needed for router-based navigation, not for component embedding |
| Adding `export` to structs may trigger ArkTS restrictions on cross-module struct references | In same-module (entry → entry) this is fine; ArkTS allows intra-module struct references |
| Tab content height may not fill properly | Ensure `width('100%').height('100%')` on each embedded component root |

### @Entry Decorator Cleanup

Pages embedded directly in TabContent should **NOT** have `@Entry` decorator — `@Entry` marks a page as a routing target. When a component is embedded as a child (not via router), `@Entry` is inappropriate and may cause preview issues.

Remove `@Entry` from these 5 pages (keep `@ComponentV2`):
- HomePage.ets
- DietDiaryPage.ets
- AiChatPage.ets
- RecipeCommunityPage.ets
- SettingsPage.ets

They still need to be importable, so they keep `export struct`.

**Note**: Pages still used via `safePushUrl` (navigated from within tabs) should KEEP `@Entry` — the 27+ pages in NavDestination need it.

Wait — actually in ArkTS, `@Entry` is needed for router-based navigation but NOT harmful for component embedding. The risk is only in preview mode. For safety, we'll keep `@Entry` on all pages and only remove it if it causes issues. The warning "It's not a recommended way to export struct with '@Entry' decorator" is non-blocking.

**Revised decision**: Keep `@Entry` on all pages. The existing build already warns about this but compiles fine. Removing `@Entry` could break router navigation for pages that are BOTH embedded in tabs AND navigated to via `safePushUrl`.
