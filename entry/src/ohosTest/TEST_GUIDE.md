## 测试环境要求

### 硬件
- HarmonyOS开发设备（真机）或模拟器（API 9+）
- 相机可用的设备（用于扫码/拍照测试）

### 软件
- DevEco Studio 4.0+
- HarmonyOS SDK API 9+
- @kit.TestKit UI测试框架（内置DevEco Studio）

## 测试执行方式

### 1. 在DevEco Studio中

1. 打开项目 `family_food_app`
2. 选择测试目标设备（真机/模拟器）
3. 运行配置：
   - **单元测试**：右键点击 `entry/src/ohosTest/ets/test/` → `Run Tests in test/`
   - 或在 `entry` 模块中配置 `ohosTest` 运行配置并执行
4. 查看测试结果：
   - DevEco Studio底部 `Run` 面板显示测试通过/失败情况
   - 失败的测试会显示具体断言信息和堆栈

### 2. 命令行执行

```bash
# 使用hvigorw运行ohosTest
cd entry
"C:\Program Files\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.bat" run ohosTest
```

### 3. 指定单个测试类

如果需要只运行某个测试类，可以临时修改 `List.test.ets`，注释掉其他测试的导入和调用，只保留目标测试。

## 常见问题

### Q1: 测试运行时报 "driver" 未找到
确保设备/模拟器已正常连接，且应用已安装部署。首次测试可能需要授予相机权限。

### Q2: UI测试因权限弹窗中止
相机和存储权限弹窗可能干扰UI测试。建议在系统设置中预先授权，或使用测试账号处理权限。

### Q3: UI测试无法找到特定文本
文本可能因页面语言或状态不同而变化。检查：
1. 当前页面是否正确（可能需要调整等待时间）
2. 文本大小写是否一致（UiTest区分大小写）
3. 组件是否在屏幕可见区域

### Q4: 单元测试编译失败
检查导入路径是否正确：
```typescript
// 正确的导入路径
import { FoodAdapterEngine } from '../../../main/ets/engine/FoodAdapterEngine';
```

### Q5: 如何新增测试用例？
1. 在相应目录创建测试文件（遵循 `*Test.ets` 命名规范）
2. 测试文件导出一个 `describe` 函数
3. 在 `List.test.ets` 中导入并注册

## 测试覆盖率说明

本测试套件覆盖以下关键路径：

- ✅ **核心引擎逻辑**：适配评分计算、预算扣减、动态修正、替代品推荐
- ✅ **数据模型序列化**：所有核心模型的 `toJson()` / `fromJson()` 序列化/反序列化
- ✅ **边界条件处理**：零值、负值、空数据、高并发、网络异常
- ✅ **UI主链路**：首页→扫码→报告→分享 的完整流程
- ✅ **二级功能**：历史记录、购物篮、会员订阅、美食平衡
- ✅ **交互验证**：成员切换、页面导航、功能按钮
